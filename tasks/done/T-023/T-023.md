## Context

Mark and range motors exist; SUPPORT already plants marks. The three universal SIDE tools still deal bare damage with no setup arming and no band shift. This task wires pure `resolveSkill` so SIDE plays apply authored marks, next Attack/SIDE reads those marks for SOUL % mults (honest, not secret buff translation), and skill-declared band moves run without requiring the caller to invent `intent.movement`.

## Spec

### Must exist when done

1. **SIDE (and ATTACK if they author `markEffects`) apply marks**
   - After hit resolution path for non-MODE roles that deal damage **or** after a successful SIDE commit: apply `skill.markEffects` the same way SUPPORT does (`addMark` with player owner / enemy target unless a later owner field exists — match current SUPPORT helper).
   - Wire → plants `off_balance`; Blastback → plants `exposed`. Consume timing remains `ATTEMPT` as authored.
   - Marks apply even if all hits miss (arm the setup; SOUL Side still “arms”). Prefer: plant marks after multi-hit block regardless of `hitsLanded` for SIDE `markEffects` that are not IMPACT-only. Do **not** plant IMPACT marks on miss if any skill uses IMPACT on SIDE (none of these three do).

2. **Next-card damage mult from spent/present attempt marks**
   - When resolving SIDE or ATTACK damage, before or at attempt-consume:
     - If `off_balance` is present as an own ATTEMPT mark (or is among marks spent this attempt): multiply that card’s total resolved damage by **1.20** (SOUL +20%).
     - If `exposed` is present/spent the same way **and** the skill is ranged (`AttackMethod.RANGED` or project-equivalent): multiply by **1.15** (SOUL +15%). Melee/non-ranged does **not** get Exposed.
   - Mults stack additively or multiplicatively in one documented pure helper; default: apply each applicable mult once to total damage after hit rolls (or per-hit consistently — pick one and test total).
   - Attempt consume still removes the mark even if every hit misses (T-004 / SOUL).
   - Do **not** use secret buff % pipelines; the bonus is mark-id driven and testable.

3. **Skill-declared band move (no voluntary spend)**
   - Author or hard-map for these ids only (prefer small optional field e.g. `bandMove: { kind: 'PULL'|'PUSH'|'SELF_RETREAT', steps: 1 }` on Skill, or id→move table in resolve — no third-party mechanics):
     - `wire_kunai_reel` → PULL foe 1 (via existing forced-move path; band is engagement range).
     - `explosive_kunai_blastback` → PUSH foe 1.
     - `backstep_shuriken` → user retreats 1 band after attempt (same engagement shift as foe approach inverse; **must not** set `playerMoveUsedThisTurn`).
   - Run after damage/mark plant (match SOUL resolve order: movement then reactions).
   - If band does not change (PUSH@LONG / PULL@CLOSE / already at edge for self-retreat): no reaction; no inventing extra move.
   - Caller `intent.movement` may still override/supplement only if product needs it; default path must work with **no** intent movement for these three skills.
