## Spec

### Must exist when done

1. **Enums (TypeScript, not string unions for roles):**
   - `CardRole`: `SUPPORT | MODE | SIDE_ATTACK | ATTACK` (UI label for SIDE_ATTACK = “SIDE”).
   - `TargetScope`: `MAIN_ATTACK | ATTACK | SIDE_ATTACK | OFFENSIVE_SKILL` (SOUL §13).
   - A combinable **tag** enum or string-enum set covering at least the SOUL examples needed for contracts (`TOOL`, `WEAPON`, `TAIJUTSU`, `NINJUTSU`, `GENJUTSU`, `MODE`, `MARK`, `DISCOVER`, `MULTI_HIT`, `PASSIVE`, plus elemental/clan tags as justified by existing `ElementType` / clan enums — do not invent new mechanics).

2. **Skill authoring fields** on `Skill` (or a clearly documented extension type used by authoring), matching SOUL §13 / HTML `#contratos`:
   - `cardRole` (required for hand-playable techniques going forward; PASSIVE may omit or use a documented non-hand rule).
   - `tags: SkillTag[]` (or equivalent).
   - `baseWeight` (v1 default **2** when omitted).
   - Optional: `hitCount?`, `discover?`, `markEffects?`, `modeInteraction?`, `perHitEffects?` as typed stubs matching the SOUL shapes (fields may be optional until later tasks fill them).

3. **ModeDefinition** interface (fields at minimum):  
   `id`, `family`, `stage?`, `maxCharges`, `activationCost`, `upkeep`, `cooldown`, `weightModifiers[]`, `enhancements[]`, `endClauses[]`  
   (TypedCost / nested types can be minimal but real — not `any`.)

4. **Mark** interface (fields at minimum):  
   `id`, `sourceSkillId`, `owner`, `target`, `duration`, `stacks`, `trigger?`, `consume?`.

5. **Skill Config / Main Attack contract (data shape only):**
   - A pure type for out-of-combat config holding at least `mainAttackId` and `modeUpkeepPriority: string[]` (or skill ids).
   - Pure helpers that encode SOUL invariants without UI:
     - Main is a designated **ATTACK** skill id; never empty when ≥1 ATTACK is in the playable loadout.
     - If Main is missing/forgotten and other ATTACKs exist: pick one uniformly via an injected `rng` and return a notify flag (do not hardcode a secret pick without notify).
     - Learning a skill does **not** change Main (helper must not reassign Main on add).
     - MODE ↔ `ActionType.TOGGLE`; SUPPORT / SIDE_ATTACK / ATTACK ↔ `ActionType.ACTIVE`; PASSIVE stays out of the 6–20 playable pool (compat helpers, not full catalog migration).

6. **Compatibility mapping helpers (pure):**  
   e.g. `actionTypeForCardRole(role)`, `isHandPlayableRole(role)`, `defaultBaseWeight()` → `2`.  
   **Forbidden in this task:** restoring or extending damage-threshold inference as the source of `cardRole`.
