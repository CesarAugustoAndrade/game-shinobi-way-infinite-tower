## Context

Tripwire is authored and can sit on the Tactical Setup, but a real enemy band change never deals the promised chip or Stun. Reaction infrastructure exists as an empty filter. This task implements the **SOUL fire contract** in pure R0: build/fire from tripwire marks, 8 damage + 60% Stun 1 on first real enemy move, no fire on non-moves, mark consumed after fire.

## Spec

### Must exist when done

1. **Pure fire helper** (name free; e.g. `fireTripwireOnEnemyMove` or generic `resolveRangeReactionsFromMarks`):
   - Input: marks setup, previous/next range (or `moved: boolean`), optional `mover: 'enemy' | 'player'`, rng for Stun.
   - If `moved === false` **or** mover is not enemy → **no** damage, no Stun, marks unchanged.
   - If enemy caused a **real** band change and a `tripwire` mark is present (id stable with authoring):
     - Deal **8** damage to the enemy (flat SOUL chip; no inventing scaling unless already on `RangeReactionDef` and tested equal to 8).
     - With **60%** chance (`rng() < 0.6` or project RNG convention documented in test): apply Stun **1** (use existing hard-control mark / buff shape consistent with T-004 hard control — one skip, not inventing double-stun rules).
     - Remove or fully consume that tripwire instance after the **first** fire (SOUL “1.er move”).
   - Multiple tripwire instances: fire **one** (document pick: oldest / first in list); do not invent multi-fire on one move unless SOUL said so (it did not).

2. **Bridge from SUPPORT plant**
   - After `tripwire_perimeter` resolves, mark must remain readable as reaction source (already duration 2, `ON_MOVE`). No need to pre-build `reactionSources` if the fire helper reads marks directly — preferred: marks are source of truth.

3. **Integration surface (pure)**
   - At minimum: unit tests call the helper after a simulated enemy `shiftRange` / voluntary approach/retreat with `moved: true`.
   - Prefer also: when `resolveSkill` applies forced movement **that represents enemy band change** OR export helper used by a thin pure `applyEnemyBandChange(state, direction)` used in tests — do **not** require full EnemyTurnSystem rewrite for AC.
   - Boundary: enemy “move” that does not change band → no fire.
