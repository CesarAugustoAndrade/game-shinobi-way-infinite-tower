## Context

Charge drain is implemented but never applied to enemies from Support play. Sealing Tag’s Silence effect is unconditional in data. This task makes pure resolve implement the **xor contract**: drain one charge from a priority enemy Mode if any ON, else apply Silence 1 — and stop treating Silence as always-on packaging for this skill.

## Spec

### Must exist when done

1. **Enemy Mode board on resolve state**
   - Extend `ResolveSkillState` with `enemyModes: ModeBoard` (empty default for fixtures).
   - Clone immutably with player `modes`.

2. **Priority pick (pure, documented)**
   - `pickEnemyModeToDrain(enemyModes): modeId | null` — among instances in ON (or equivalent active) state, pick **one**:
     - Preferred: first ON in `modeUpkeepPriority`-style order if a priority list is passed; else **stable order of `instances` array** (first ON).
   - Do not invent DPS-based priority.

3. **Sealing Tag / drain-or-silence SUPPORT resolve**
   - When resolving SUPPORT `sealing_tag_chakra_lock` (or any SUPPORT with `modeInteraction.consumeCharges` targeting enemy Modes — minimum AC is this skill id):
     - If `pickEnemyModeToDrain` returns an id: `drainCharges(enemyModes, id, 1, turnIndex)`; on success update `enemyModes`; **do not** apply Silence for that cast.
     - If no ON enemy Mode: apply **Silence 1** on enemy (buff/status via existing effect pipeline or a pure mark/buff append — project-consistent; must be observable in result state).
   - Invalid resolve still consumes nothing (existing T-007 rules).

4. **Authoring honesty**
   - Sealing Tag must **not** keep a permanent always-on Silence effect that fires even when a Mode was drained. Prefer remove unconditional Silence from `effects[]` and apply Silence only in resolve’s no-Mode branch (or gate effect application). Description already states the xor.
