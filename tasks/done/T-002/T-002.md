## Spec

### Must exist when done

1. **Turn phase model (pure):**  
   Named phases in fixed SOUL order (names may be enum or const union):
   1. Mode upkeep (by `modeUpkeepPriority[]` when provided)
   2. Ticks then regeneration (upkeep **must not** spend regen granted in this same phase-2)
   3. Snapshot + draw (hook / pure call site — may delegate to existing `drawNewTurnHand` temporarily)
   4. Player support/mark duration decrement (no-op if no Marks/supports yet)
   5. Actions (player then enemy — orchestration may remain in existing turn systems)
   6. Virtual discard of hand (document + pure helper; full deck deletion is later draw task)

   Provide a pure **phase runner** or ordered API such that unit tests can assert **phase order** and that mode-upkeep resource payment is attempted **before** regen mutates chakra/HP pools used for that payment.

2. **Cooldown semantic (`readyOnTurn`):**  
   - Pure functions, SOUL formula: used on turn **T** with authored cooldown **N** → `readyOnTurn = T + N + 1`.  
   - Skill is **blocked** for play on turns `T+1 … T+N`; **ready** on `T+N+1`.  
   - Example: **N = 2** → blocked on the next **two** player hands/turns; usable on the third after use.  
   - CD does **not** remove the card from the draw pool (weight −1 is draw task); this task only defines **playability** vs turn index.  
   - Prefer storing `readyOnTurn` (or dual-write with migration from `currentCooldown`) in pure helpers; if live path still uses `currentCooldown`, map so AC1 scenario holds for the pure API and any wired live gate.

3. **Encounter boundary (pure):**  
   One function (e.g. `resetCombatFrontier` / extend `createCombatState` consumers) that at **start of each combat** resets:
   - skill cooldowns / `readyOnTurn` to ready  
   - active Modes / charges (empty collection OK if Modes not implemented)  
   - Marks / Tactical Setup (empty OK)  
   Explicit: **no** persistence via Heat or Encounter Chain. Document that callers must use this at combat start.

4. **Mode upkeep hook (minimal, not full Mode machine):**  
   Given an ordered list of active mode upkeep costs (CP/HP) and priority ids: pay what is payable in order; failed payment ends that mode and starts its cooldown **before** phase-2 regen; later modes in the list still attempt. HP upkeep must not reduce HP below **1** (Mode off instead) — SOUL §8 HP upkeep floor, even if only tested with fixture costs.
