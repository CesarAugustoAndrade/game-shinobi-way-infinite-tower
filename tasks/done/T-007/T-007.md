## Context

Hit math and playability helpers exist. Missing is a single pure **commit orchestrator** that plays legal roles in SOUL order and refuses invalid intents without side effects. This task adds that R0 API and optionally thin-wraps live combat to call it.

## Spec

### Must exist when done

1. **`resolveSkill(intent, state, rng)` pure API** (name flexible) implementing SOUL order:
   1. Validate hand snapshot / skill id, AP, resources, range, hard gates, role-legal play (PASSIVE never via this path).
   2. If invalid → return reject with **zero** mutation of player/enemy/combat (no AP/CP/HP/CD/marks/charges spent).
   3. If valid → **commit** AP + CP/HP (FREE_FIRST: chakra only, per T-006/SOUL) + set `readyOnTurn` / CD semantic (T-002 helper or equivalent).
   4. Consume **own attempt-marks** + declared **Mode charges** (ports/stubs OK).
   5. Resolve by `cardRole`:
      - **MODE:** activation / manual-off / family replace hooks (call Mode system or stub).
      - **SUPPORT:** apply marks/setup/discover hooks without requiring damage > 0.
      - **SIDE_ATTACK / ATTACK:** damage path with `hitCount` N independent rolls; enhanced bonus only if Mode/setup rules declare (fixture flags OK).
   6. If **≥1 hit**: consume enemy impact-marks; once-per-card effects/artifacts; else skip impact consume.
   7. Apply `perHitEffects` when flagged.
   8. Resolve declared movement then range reactions (T-006 helpers).

2. **Role legality:**  
   Playing requires authored `cardRole` (from T-001). Do not infer role from damage. TOOL is never a role. Offensive = ATTACK | SIDE_ATTACK for damage helpers only.

3. **Miss / fail after commit:**  
   Costs and attempt-consumes stay spent; impact marks preserved on total miss (SOUL §9) — must be testable.

4. **Integration stance:**  
   Prefer new module (e.g. `ResolveSkillSystem.ts`) that `useSkill` can delegate to, or parallel pure API with tests as source of truth. Delete dead duplicate gate logic only when safely replaced (no dual normative paths long-term).
