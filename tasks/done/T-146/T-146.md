## Context

After a Discover SUPPORT resolves, combat holds `pendingDiscover` with up to 3 candidates. The player must pick one; the chosen skill snapshots into the hand (possibly disabled if on CD); pending clears.

## Spec

### Must exist when done

1. **R1 commit API**
   - `useCombat` (or thin helper it calls) exposes e.g. `commitDiscover(chosenSkillId)` that:
     - Reads `combatState.pendingDiscover` + resolve-shaped state / hand / marks / skills pool as needed.
     - Calls `commitDiscoverChoice` (or equivalent adapter).
     - Writes back updated `hand`, `marks`, clears `pendingDiscover`, updates player/combat state immutably.
     - No-ops / refuses safely when no pending or unknown id.

2. **R2 picker UI**
   - When `pendingDiscover` is set, show a picker listing up to 3 candidates (name/role/CD-disabled cue).
   - Player click/confirm calls `commitDiscover`.
   - Prefer blocking other hand plays while pending (or document Pass-only) so Discover isn’t skipped silently — minimum: visible modal/panel until choice.
   - Accessibility: text labels, not color-only disabled.

3. **No R0 reauthor**
   - Do not change Discover weight algorithm or candidate count rules.
