## Spec

### Must exist when done

1. **Live turn-start uses SOUL phase order 01–04** for player turn open:
   1. Mode upkeep by `modeUpkeepPriority` (from Skill Config / combat state; empty = stable default order of active modes).
   2. Ticks/regen **after** upkeep (upkeep **not** funded by same-turn regen).
   3. Snapshot + draw hand of 4 via existing `drawNewTurnHand` / pool (virtual discard — no deck pile restore of unplayed cards as a discard stack).
   4. Decrement **player** support durations + marks **after** draw (T-002 helper already in clock).

2. **Mode board is first-class on the live path:**
   - Read `combatState.activeModes` (or equivalent ModeBoard) into the clock.
   - Write back remaining modes, ended modes (failed upkeep → Mode ends + CD via T-005/`readyOnTurn`), updated chakra/HP, marks, hand, and `turnIndex` as already modeled.
   - HP upkeep that would be lethal: Mode off, player HP **≥ 1** (SOUL §8 / §16) — assert via existing Mode/clock helpers, not a new rule.

3. **Legacy toggle-only upkeep is not the normative Mode path:**
   - When Modes are present on the board, their upkeep goes through the Mode/clock pipeline (CP or HP per definition), not only `skill.upkeepCost` chakra toggles.
   - Delete or stop calling dead “toggle chakra upkeep as the Mode system” for board-tracked Modes (no dual normative upkeep). Untracked legacy toggles without Mode ids may remain until T-011 links rows — document in Notes; do not invent Mode ids here.

4. **R1 persistence:** `useCombat` (or sole upkeep caller) applies returned player pools, hand, AP budget, modes, marks, turnIndex immutably. No React combat math beyond state projection.
