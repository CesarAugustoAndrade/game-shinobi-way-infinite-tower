## Context

Pure contracts and draw/upkeep motors exist. The run has no durable Skill Config on the player, so Main is never assigned, learning cannot preserve Main, and turn-start Mode priority cannot read a player-owned list. This task **adds Skill Config to live player state**, runs `ensureMainAttack` on loadout mutations and combat entry, **blocks config mutation while in combat**, and **feeds** `mainAttackId` / `modeUpkeepPriority` into existing draw and (when T-012 lands) upkeep call sites.

## Spec

### Must exist when done

1. **Player owns Skill Config**
   - `Player` (and any run-save / new-run factory that must stay type-consistent) carries a `skillConfig: SkillConfig` with `mainAttackId: string | null` and `modeUpkeepPriority: string[]`.
   - New runs / fixtures initialize empty config then run `ensureMainAttack` when the loadout has ≥1 ATTACK (`cardRole === ATTACK` or T-001 authoring map when used).

2. **Main invariants on live loadout paths (call pure helpers — do not reimplement RNG rules)**
   - On combat start (or first need): if Main empty/invalid and loadout has ATTACK ids → `ensureMainAttack` with injected rng; surface `notified` to caller (log or flag) when auto-picked.
   - Learning / adding a skill uses `withAddedSkill` (or equivalent): **does not** change an already-valid Main.
   - Forgetting / removing the current Main skill → re-run `ensureMainAttack` so Main is never stuck on a missing id when another ATTACK remains.
   - Never invent Main by damage/DPS heuristics.

3. **Combat lock**
   - While `GameState.COMBAT` (or project-equivalent “in encounter”), player cannot reassign `mainAttackId` or reorder `modeUpkeepPriority` through the live mutation API used by exploration. R0 helper may be `assertSkillConfigEditable(gameState)` or mutations simply not called from combat hooks — prove via test that combat-path code does not rewrite config.

4. **Feed existing motors**
   - `processUpkeep` / draw path passes `mainAttackId` from `player.skillConfig` into `WeightContext`.
   - `modeUpkeepPriority` is available on player for T-012 / `runTurnStartClock` consumers (export on upkeep input or combat state seed). Empty array remains valid (stable default order of active modes).
