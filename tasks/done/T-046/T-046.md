## Spec

### Must exist when done

1. **Authoring (`kai`)**
   - `cardRole: CardRole.SUPPORT`.
   - Costs: **AP 1**, **CP 3**, **CD 2**, HP 0; `baseDamage: 0`; ranges ANY.
   - Cleanse contract (description + structured field optional): remove **player** Confusion and Silence; remove **one** MENTAL mark that is hostile to the player (see §2); if any removal occurred, **+3** player chakra after pay (net can be −3+3 = 0 when cleanse hits).
   - Remove primary CALMNESS +0.5×3 identity.
   - Honest description: cleanse Confusion/Silence + one MENTAL mark; if any cleanse, recover 3 CP.

2. **`resolveSkill` SUPPORT cleanse order**
   - Pay AP/CP/CD commit first (chakra −3), then cleanse, then conditional refund.
   - **Confusion:** strip all `playerBuffs` whose `effect.type === CONFUSION` (or equivalent project confusion id).
   - **Silence:** strip all `playerBuffs` whose `effect.type === SILENCE`.
   - **One MENTAL mark:** remove exactly **one** mark from `state.marks` that is **on the player** (target PLAYER) and matches a **documented allowlist** of mental/control mark ids used by genjutsu setup (start with ids already in codebase such as `fear` if self-targeted, plus any player-targeted mental control marks tests plant as `mental_bind` / fixture id). SOUL §9 has no separate MENTAL MarkFamily — **do not invent** a new family enum for this task unless unavoidable; prefer id allowlist + optional `family === HARD_CONTROL` for one strip candidate. Prefer first matching mark in array order. **Do not** strip enemy-targeted setup the player planted (e.g. enemy `chakra_point`).
   - **Refund:** if any buff or mark was removed, `pools.chakra += 3` (no cap beyond existing max if present; if no maxChakra on state, uncapped is OK for pure tests).
   - If nothing to cleanse: still pay full cost; **no** refund; `ok: true`; `damageDealt === 0`.
   - No Mode mutation; no Terrain; no Discover.

3. **Observability**
   - Return state with updated `playerBuffs`, `marks`, `pools.chakra`.
   - Prefer result flag or AC via state diff only (no UI).
